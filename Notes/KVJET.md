我们把数据哈希到一致性哈希环上，每个环上节点是一个小集群，小集群内部使用 Raft 来做管理
每个节点有多个归属，如：同时作为 PD，作为集群 A 的 master，作为集群 B 的 replica
每个小集群有一个自己的 id(自增的)，并且用这个维护一致性哈希环上的信息
暂定有多少个节点，就有多少个集群，并且每个集群的节点个数是定死的，我们假定是 3 个
那么 0 号集群就得有第 0 号节点、第 1 号节点、第 2 号节点
1 号就有 1、2、3
以此类推

### 客户端行为

连接到某个节点后，发 GETNETWORK 获取完整网络拓扑

SET 命令：
 1. 计算哈希值，确定 key 归属的 Raft 组
 2. 发给该组的 master 节点
	- 指令成功，收到 OK
	- 指令失败，节点已迁移，收到 MOVED，此时应该发 GETNETWORK，获取拓扑后重试，重发 SET 命令

 GET 命令：
1. 计算哈希值，确定 key 归属的 Raft 组
2. 从该组的副本列表中随机选一个节点发送（master 也算一个可读副本）
	- 指令成功，收到 VALUE
	- 指令失败，节点已迁移，收到 MOVED，此时应该发 GETNETWORK，获取拓扑后重试，重发 GET 命令
