# SQL注入

- **根本原因**：应用程序错误地信任用户输入，**直接将未经处理的数据拼接到 SQL 查询语句中，导致代码与数据混淆。**
- **攻击原理**：攻击者输入精心构造的 SQL 命令字符串（如 `' OR '1'='1`），欺骗数据库执行非预期的命令。
- **探测方法**：
    - **单引号探测**：添加 `'` 观察是否报错。
    - **逻辑探测**：构造永真（`and 1=1`）和永假（`and 1=2`）条件观察页面差异。
    - **盲注探测**：利用时间延迟（`SLEEP(5)`）或布尔逻辑判断。
- **危害**：权限绕过（免密登录）、敏感数据泄露、数据库被篡改或删除

# XSS攻击

- **根本原因**：网站对用户输入过滤不足，导致恶意客户端**脚本（通常是 JavaScript）被注入并执行**。
- **主要类型**：
    1. **反射式 (Reflected)**：非持久性。脚本包含在 URL 参数中，服务器将其“反射”回浏览器执行。需诱骗用户点击链接。
    2. **存储式 (Stored)**：持久性。脚本永久存储在服务器数据库（如评论区、个人资料）。任何访问该页面的用户都会受害。
    3. **DOM式**：漏洞完全存在于客户端代码中，通过修改页面的 DOM 环境触发，不经过服务器。
- **危害**：窃取 Session Cookies（会话劫持）、篡改网页内容、重定向用户到钓鱼网站、键盘记录。

# CSRF攻击

- **定义**：跨站请求伪造。**诱骗受害者在已认证的浏览器中提交恶意请求**。
- **原理**：利用网站对用户浏览器的信任。浏览器在发送请求时会自动携带该网站的 Cookie。攻击者诱导用户访问恶意页面，该页面发起指向受信任网站的请求，服务器无法区分该请求是用户自愿还是被伪造的。
- **特点**：攻击者无法获取数据（因为同源策略），但可以**冒充用户执行操作**（如转账、修改密码、发帖）。

# 相应的防御方法

#### 1. SQL注入防御

- **预编译语句与参数化查询**（最有效）：将 SQL 结构与数据分离，使输入仅被视为参数而非代码。
- **最小权限原则**：数据库账户仅授予完成任务所需的最小权限（禁止 root 运行）。
- **输入校验**：使用白名单验证输入格式。
- **使用存储过程**：避免在存储过程内部使用动态拼接。

#### 2. XSS攻击防御

- **输出编码**（核心）：在数据显示到 HTML、属性、JS 或 URL 上下文前进行转义（如 `<` 转为 `&lt;`）。
- **输入验证**：对用户提交的数据进行严格过滤。
- **内容安全策略 (CSP)**：通过 HTTP 头限制脚本来源，禁止内联脚本。
- **HttpOnly Cookie**：防止 JS 读取 Cookie，有效防范会话劫持。

#### 3. CSRF攻击防御

- **CSRF Token**（最常用）：服务器为每个表单生成唯一的随机令牌，提交时校验。攻击者无法预测此令牌。
- **SameSite Cookie 属性**：设置 `Strict` 或 `Lax`，限制第三方请求携带 Cookie。
- **检查 Referer 或 Origin 头**：验证请求是否来自受信任的域名。
