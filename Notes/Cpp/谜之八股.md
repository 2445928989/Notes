### COW 之谜

C++10 以前，string 其实是一个 COW（写时复制）的数据结构，它内部维护了一个指向 char\* 常量的指针，跟 Java 的字符串差不多（你要是强行修改的话，他会搞一个新的字符串常量），然后对于字符串常量维护一个引用次数，没有了再考虑回收它。后来就取消了，改成了 string 每个人自己有自己独立的资源。（因为不太安全也不太符合直觉）

### 为什么堆区分配比栈区慢？

栈区分配内存是简单的指针自增自减，而堆区要维护一些比较复杂的数据结构（如链表红黑树）与算法（first-fit 之类的），要涉及到遍历、分割合并、以及多线程环境下的加锁操作

栈区是 OS 为程序分配的一块大小，程序要怎么用怎么用，没必要进入内核态，但是栈区是需要使用系统调用来向操作系统申请，要经过内核态用户态的切换

栈区内部的地址都是连续的，cache 的命中率比较高，堆区都是碎片，内存局部性太差

栈区分配内存的释放时机是确定的，没有运行时决策，而堆区什么时候释放是由程序员决定的，涉及到分支预测失败

### Malloc?

malloc 本质上是一个用户态的内存池管理器。实际上它分配的是虚拟内存，它通过 mmap (大内存，放到文件映射段) brk（小内存，放到堆段） 之类的系统调用向 OS 申请一大块内存，再在用户态管理该内存池，这样可以减少系统调用的次数，减小开销。

其中，brk 在 free 后不会返还，mmap 会。

### NEW?

其实跟 malloc 的区别主要集中在会不会调用构造函数罢了，都是批发一大块内存然后在用户态做内存池管理。但是你也可以覆写 new，这样的话就不一样了

### 分支预测？

遇到 if 的时候，如果得到 if 的结果很慢，那么 CPU 在得到 if 的结果之前会先提前运行一个方向的指令并得到结果，如果 if 是对的，那就直接应用这个结果，否则的话要清空流水线。现代分支预测器一般都是动态的，加上有 -O2 之类的编译器优化技术，其实我们不是很有必要写__builtin_expect 这样的人工预测标记

### Cache 的写入？

两种策略，第一种是写直达，第二种是写回，第一种是同时写到内存和 cache 里，第二种是只写到 cache 里，淘汰了再写到内存里。显然第二种的效率更好，但是会带来缓存一致性问题。

### 缓存一致性？

那你得保证不同核心之间缓存一致吧？要不你的修改就作废了，我们引入一个 MOESI 协议，一个状态机，记录了每个数据的状态：

Modified，已修改（淘汰的时候写回内存）
Owned，拥有（修改过，别人也能有，但是我的是最新的，我负责写回）
Exclusive，独占
Shared，共享
Invalidated，已失效

当我要写的时候，要先通知所有人把自己的这份缓存失效，然后把我自己的修改以后改成 M 状态，等以后淘汰的时候再写回

### 为什么要虚拟内存？

1. 虚拟内存可以防止进程之间互相影响（读写同一块内存），解决了多进程地址冲突问题
2. 虚拟内存技术可以通过 swap 让系统运行总内存需求超过物理内存大小的程序
3. 提供了一个统一的抽象接口，让程序员只关心程序是怎么运作的而无需考虑物理内存的不同配置
4. 可以通过映射到同一个物理内存地址来实现 COW 以及进程间通信等内存共享技术
5. 可以实现资源的按需加载，程序申请了很多内存，但是我可以只加载程序需要的部分

### 缺页中断？

Malloc 调用 mmap 或者 brk 得到的内存，实际上是 CPU 承诺给他的内存，但是实际上还没给呢，当访问到页表里实际上没给的物理内存时，会产生一个缺页中断，切换到内核态分配内存然后再切换回来。

COW 触发的时候也会哦

Swap 的时候也会哦

爆栈了，但是只爆了一点点，也会触发然后接着跑

访问只读/不可读部分的时候，或者访问非法地址的时候，也会触发，内核会发一个 SIGSEGV，然后你就死咯

### 为什么要设计内核态和用户态？

1. 保证用户态程序不会破坏内核正常运行，起到一个隔离保护内核的功能
2. 可以做权限控制
3. 方便给程序员提供一套统一的抽象接口而不需要关心硬件的具体实现

### 没内存了？

内存紧张的时候会启动后台回收线程回收内存，还不行就上直接内存回收，再不行就找个不省油的灯直接沙了。

回收的时候会根据 LRU ，先回收页缓存（文件缓存、inode 缓存之类的），如果有脏数据还得启动 flush 线程写回去，然后考虑回收匿名页（堆上 malloc 或者栈上局部变量、COW 的私有页之类的），但是有可能还得用，所以要 swap 到硬盘上。

### 对一个 socket wirte 和直接 cout 有什么区别？

std:: cout 维护了一个用户态缓冲区，你写东西进去他会先进用户态缓冲区，然后视缓冲区里面东西多少来触发 flush，扔到内核态缓冲区里，然而 write 是一个系统调用，你写进去啥他就直接扔到内核态缓冲区了 
扔进去以后呢？当然是不管了，OS 自己会找时机处理这些缓冲区里的东西的。
因此，一般我们用 socket 的时候都要自己维护一个 buf 数组。

### 怎么处理预读失效、缓存污染问题

可以把链表分成冷数据和热数据两部分，预读的那些资源放到冷数据里，真的读到了再放到热数据里，分别维护 LRU。

为了避免缓存污染，可以让冷数据被访问第二次的时候再放到热数据里，或者限定你必须跟第一次访问有一定时间差（因为活得越久，越有可能是热数据）

或者干脆直接上 LFO（least frequently used），维护一个计数器。但是对突发热点适应性不强，而且开销比较大，所以 mysql 和 linux 没用它。

### Function？类型擦除？

首先我们来想这么一个问题，你想要把函数指针、lambda、function 扔到一个 vector 里，然后通过 v\[x\]\() 来调用这里边的函数
传统的做法是你定义一个基类，然后重载它的 operator ()，声明成虚函数，再搞一堆子类继承这个基类，也重载一下 operator ()，然后让 vector 的模板是 Base\*，用那种传统多态来实现这个功能，但是太繁琐了，而且我还得手动 delete 指针（或者上智能指针）。
所以我们需要一个不存储具体类型，只通过一个公共接口来调用函数的东西。
也就是 function<void()>。
在看 function 之前，我们先来看类型擦除的几种方法。

类型擦除，也就是可以让你不关心它具体是什么类的对象，而是只关心它提供的接口，用同一个名字调用不同的种类。

第一种，最笨的，写一个函数，然后手动标识它是哪种玩意

```cpp
// 类型擦除的打印函数
// typeId: 0 表示 Circle, 1 表示 Square
void printShape(void* shape, int typeId) {
    if (typeId == 0) {
        Circle* c = static_cast<Circle*>(shape);
        c->print();
    } else if (typeId == 1) {
        Square* s = static_cast<Square*>(shape);
        s->print();
    }
}
```
显然这个东西很蠢，我还得手动管理 typeId。
然后第二种是上面讲的通过虚函数来实现的
```cpp
// 1. 抽象基类：擦除具体类型，只暴露 print 操作
class Shape {
public:
    virtual ~Shape() = default;
    virtual void print() const = 0;
};
// 2. 具体形状：保留真实类型，实现 print
class Circle : public Shape {
    double radius_;
public:
    Circle(double r) : radius_(r) {}
    void print() const override {
        std::cout << "圆形，半径 = " << radius_ << std::endl;
    }
};
class Square : public Shape {
    double side_;
public:
    Square(double s) : side_(s) {}
    void print() const override {
        std::cout << "正方形，边长 = " << side_ << std::endl;
    }
};
```
但是这样写起来非常屎。首先你必须得用基类指针或者引用才能跑起来，而且你必须指定它们要继承基类，那有没有办法可以让他们不用继承基类呢？

比如，现在告诉你 Circle 和 Square，它们没有继承同一个 Shape 父类，而且你不能改源码，你还想实现一个统一的接口来调用它们不同的 print 方法

人话就是，
1. 你先搞一个非模板抽象基类 A，定义 do_print() 纯虚方法
2. 然后搞一个模板派生类 B\<T\> ，有 T 类型对象 obj，覆写 do_print() 方法为调用 T.print() 
3. 再搞一个包装类 C，有一个 A\* 成员，然后定义一个 print() 方法，调用 A->do_print()

这样你就能用 C.print() 方法统一调用不同类的同名接口了。
看代码：
```cpp
// 1. 非模板抽象基类 A
class A {
public:
    virtual ~A() = default;
    virtual void do_print() const = 0;
};
// 2. 模板派生类 B<T>
template <typename T>
class B : public A {
    T obj_;
public:
    B(const T& obj) : obj_(obj) {}
    void do_print() const override {
        obj_.print();   // 调用具体类型的 print 方法
    }
};
// 3. 包装类 C
class C {
    std::unique_ptr<A> ptr_;
public:
    template <typename T>
    C(const T& obj) : ptr_(std::make_unique<B<T>>(obj)) {}
    void print() const {
        ptr_->do_print();
    }
};
// 具体类型：Circle
class Circle {
    double radius_;
public:
    Circle(double r) : radius_(r) {}
    void print() const {
        std::cout << "圆形，半径 = " << radius_ << std::endl;
    }
};
int main() {
    // 创建 Circle 对象
    Circle c(5.0);
    // 通过 C 包装 Circle
    C wrapper(c);
    // 通过 C 统一调用 print()
    wrapper.print();   // 输出：圆形，半径 = 5
    return 0;
}
```

Function 的实现也是类似的，不过由于是基于多态来实现的，所以会有遍历虚表的开销以及解引用指针的开销。还有拷贝的时候每次需要 new 一个新的函数自身出来。
但是 function 做了优化，当 new 的这个函数不是很大的时候，它会直接在栈上开，避免 malloc 开销。

### 可见性

1. Static 当前文件可见（不对外暴露）
2. Global 外部链接，需配合 extern
3. Extern 引用其他文件的 global

### 多继承的时候 vptr 的行为？

在多继承的时候子类对象的 vptr 会有多份，分别指向不同版本的虚函数表
用不同的基类指针指向该对象的时候，调用函数访问的 vptr 是不一样的，访问的虚函数表也是不一样的
而且即使俩指针指向的是同一个对象，它们指向的地址也会不一样（偏移 8 字节的倍数，取决于继承表是怎么写的）。因为他得知道用哪个版本的 vptr

### 虚表大小？

8*(虚函数个数+1)
多的那个 1 是一个指向 type_info 的指针，用来实现 RTTI
