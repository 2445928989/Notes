### COW 之谜

C++10 以前，string 其实是一个 COW（写时复制）的数据结构，它内部维护了一个指向 char\* 常量的指针，跟 Java 的字符串差不多（你要是强行修改的话，他会搞一个新的字符串常量），然后对于字符串常量维护一个引用次数，没有了再考虑回收它。后来就取消了，改成了 string 每个人自己有自己独立的资源。（因为不太安全也不太符合直觉）

### 为什么堆区分配比栈区慢？

栈区分配内存是简单的指针自增自减，而堆区要维护一些比较复杂的数据结构（如链表红黑树）与算法（first-fit 之类的），要涉及到遍历、分割合并、以及多线程环境下的加锁操作

栈区是 OS 为程序分配的一块大小，程序要怎么用怎么用，没必要进入内核态，但是栈区是需要使用系统调用来向操作系统申请，要经过内核态用户态的切换

栈区内部的地址都是连续的，cache 的命中率比较高，堆区都是碎片，内存局部性太差

栈区分配内存的释放时机是确定的，没有运行时决策，而堆区什么时候释放是由程序员决定的，涉及到分支预测失败

### Malloc?

malloc 本质上是一个用户态的内存池管理器。实际上它分配的是虚拟内存，它通过 mmap (大内存，放到文件映射段) brk（小内存，放到堆段） 之类的系统调用向 OS 申请一大块内存，再在用户态管理该内存池，这样可以减少系统调用的次数，减小开销。

其中，brk 在 free 后不会返还，mmap 会。

### NEW?

其实跟 malloc 的区别主要集中在会不会调用构造函数罢了，都是批发一大块内存然后在用户态做内存池管理。但是你也可以覆写 new，这样的话就不一样了

### 分支预测？

遇到 if 的时候，如果得到 if 的结果很慢，那么 CPU 在得到 if 的结果之前会先提前运行一个方向的指令并得到结果，如果 if 是对的，那就直接应用这个结果，否则的话要清空流水线。现代分支预测器一般都是动态的，加上有 -O2 之类的编译器优化技术，其实我们不是很有必要写__builtin_expect 这样的人工预测标记

### Cache 的写入？

两种策略，第一种是写直达，第二种是写回，第一种是同时写到内存和 cache 里，第二种是只写到 cache 里，淘汰了再写到内存里。显然第二种的效率更好，但是会带来缓存一致性问题。

### 缓存一致性？

那你得保证不同核心之间缓存一致吧？要不你的修改就作废了，我们引入一个 MOESI 协议，一个状态机，记录了每个数据的状态：

Modified，已修改（淘汰的时候写回内存）
Owned，拥有（修改过，别人也能有，但是我的是最新的，我负责写回）
Exclusive，独占
Shared，共享
Invalidated，已失效

当我要写的时候，要先通知所有人把自己的这份缓存失效，然后把我自己的修改以后改成 M 状态，等以后淘汰的时候再写回

### 内存模型

1. 代码段 (.text) 存代码的
2. 常量段 (.rodata) 存生命周期等于程序生命周期的常量
3. 数据段 (.data) 存已初始化的全局/静态变量的
4. BSS 段 (.bss) 存未初始化的全局/静态变量
5. 堆段 (Heap) 你懂得~
6. 文件映射段存共享库、mmap 映射的区域、共享内存的 
7. 栈段 (Stack) 你懂得~

### 为什么要虚拟内存？

1. 虚拟内存可以防止进程之间互相影响（读写同一块内存），解决了多进程地址冲突问题
2. 虚拟内存技术可以通过 swap 让系统运行总内存需求超过物理内存大小的程序
3. 提供了一个统一的抽象接口，让程序员只关心程序是怎么运作的而无需考虑物理内存的不同配置
4. 可以通过映射到同一个物理内存地址来实现 COW 以及进程间通信等内存共享技术
5. 可以实现资源的按需加载，程序申请了很多内存，但是我可以只加载程序需要的部分
