
传统维护 socket 的时候会给每个连接分配一个进程/线程来处理 IO，这就导致了资源浪费（cpu 调度开销太大），所以引入了各种复用 IO，比如 select poll epoll，它们可以让你不用多开线程就能处理多个连接的 IO 事件

select 维护了一个实际上是 bitset 的 fd_set

```cpp
int select(int nfds, 
		   fd_set *_Nullable restrict readfds,
           fd_set *_Nullable restrict writefds,
           fd_set *_Nullable restrict exceptfds,
           struct timeval *_Nullable restrict timeout);
// nfds-最大fd编号
// readfds-记录哪些fd有读事件
// writefds-记录哪些fd可写
// exceptfds-记录哪些fd有异常
// timeout-超时时间
// 修改传入的fd_set，记录哪些fd有事件

void FD_CLR(int fd, fd_set *set);	// 清空fd_set
int  FD_ISSET(int fd, fd_set *set);	// 查询fd_set某一位
void FD_SET(int fd, fd_set *set);	// 设置fd_set某一位为1
void FD_ZERO(fd_set *set);			// 设置fd_set某一位为0
```

每次你可以调用 select 来记录有哪些 socket 有读事件（监听 socket 监听到有连接请求也是一种读事件），再遍历 fd_set 处理这些事件（说白了就是多线程改 for 循环了，但是因为这么做你可以直接忽视没有 IO 请求的 socket 导致比多进程或者多线程更优）

然而，一般来说 select 能维护的连接只有 1024 个，所以引入了 poll 和 epoll

Epoll 是一个事件驱动型的 IO 复用模型

你需要在内核里创建一个 eventpoll 对象，他会关注你注册的所有 fd ，并用一个红黑树来维护有哪些 fd，当某个 fd 有事件的时候，它会调用对应的回调函数，然后把这个 fd 挂到事件链表上返回。

可以理解成其实就是一个维护了消息队列和 fd 集合的数据结构，因为它支持事件驱动所以不需要每次遍历，而且有新东西的时候可以增量修改，而不需要像 select 一样把整个 fd_set 每次传递给内核，非常好用。

```cpp
int epoll_create(int size);
// 创建一个 epoll 实例，返回其文件标识符；size 已废弃但需 >0

int epoll_create1(int flags);
// 同上，flags 可为 0 或 EPOLL_CLOEXEC(当进程exec的时候自动关闭)

int epoll_ctl(int epfd, int op, int fd, struct epoll_event *event);
// epfd	-epoll的fd
// op	-控制epoll行为EPOLL_CTL_ADD/EPOLL_CTL_MOD/EPOLL_CTL_DEL
// event-监控的事件类型

int epoll_wait(int epfd, struct epoll_event *events, int maxevents, int timeout);
// 等待事件，就绪事件填充到 events，返回事件个数；timeout 毫秒，-1 阻塞

struct epoll_event {
    uint32_t events;     // 事件掩码（EPOLLIN, EPOLLOUT, EPOLLET...）
    epoll_data_t data;   // 用户数据，通常放 fd 或自定义指针
};
typedef union epoll_data {
    void *ptr;
    int fd;
    uint32_t u32;
    uint64_t u64;
} epoll_data_t;
// 这个data里边放的东西是程序员自定义的，ctl把这个data结构体绑定到fd对应的事件上，然后wait发现这个fd有事件的时候会把data再传回来扔到那个events数组里边，非常方便
```

```cpp
// example
// 一个epoll服务端

int listensock = ...; // 一个已经打开监听模式的监听socket
int ep = epoll_create1(0); // 创建eventpoll对象
int flags = fcntl(listensock, F_GETFL, 0);
fcntl(listensock, F_SETFL, flags | O_NONBLOCK);
epoll_event ev{};
ev.events = EPOLLIN | EPOLLET; // 这里用了边缘触发
ev.data.fd = listenfd;
epoll_ctl(ep, EPOLL_CTL_ADD, listenfd, &ev); // 先把监听socket扔进去
int max_event = 10;
epoll_event events[max_event]; // 用来接收事件的event数组
char buf[1024];
while (1) {
    int event_num = epoll_wait(ep, events, max_event, -1); // 阻塞，直到有事件
    for (int i = 0; i < event_num; i++) {
        int fd = events[i].data.fd;
        if (fd == listenfd) {
            int fd_;
            while (1) { 
            	// 因为用了边缘触发，所以一次一定要全处理完直到EAGAIN!!!!!!
                fd_ = accept(fd, 0, 0);
                if (fd_ == -1) {
                    if (errno != EAGAIN && errno != EWOULDBLOCK) {
                        std::cerr << "accept error\n";
                        close(listenfd);
                        return -1;
                    } else if (errno == EINTR) {
                        continue;
                    } else {
                        break;
                    }
                }
                ev.data.fd = fd_;
                std::cout << "connect to " << fd_ << '\n';
                // 设置非阻塞读取，用于一次尽量读完
                int flags = fcntl(fd_, F_GETFL, 0);
                fcntl(fd_, F_SETFL, flags | O_NONBLOCK);
                epoll_ctl(ep, EPOLL_CTL_ADD, fd_, &ev);
            }
        } else {
            int sz = 0;
            // 非阻塞地读取，直到读到0代表EOF，断开连接，或者读到-1代表这次读完了或者报错
            // 检查一下是不是EAGAIN，不是就是真错了
            while ((sz = read(fd, buf, sizeof(buf))) > 0) {
                buf[sz] = 0;
                std::cout << "write " << buf << " to " << fd << '\n';
                write(fd, buf, sz);
            }
            if (sz == 0) {
                std::cout << "disconnect to " << fd << '\n';
                epoll_ctl(ep, EPOLL_CTL_DEL, fd, NULL);
                close(fd);
            } else if (sz == -1) {
                if (errno != EAGAIN && errno != EWOULDBLOCK) {
                    std::cout << "disconnect to " << fd << '\n';
                    epoll_ctl(ep, EPOLL_CTL_DEL, fd, NULL);
                    close(fd);
                }
            }
        }
    }
}
close(listenfd);
// !!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
// 请注意，如果设置了边缘触发，一次一定要把事件表里的所有fd的所有事务都处理完，不然会苦等……
```



# 代码审查：Handler. Cpp 和 Server. Cpp

## 严重问题

### 1. **Server. Cpp - epoll_step () 中的索引错误** ⚠️ 最严重

```cpp
void Server::epoll_step() {
    int event_num = epoll_wait(epoll_fd, events, MAX_EVENTS, -1);
    for (size_t i = 0; i < event_num; i++) {
        if (events[i].data.fd == server_sock.fd()) {
            while (accept()) { }
        } else {
            std::string str = recv(connections[i]);  // ❌ 错误！
            //                                 ↑ 这是events数组的下标，不是fd！
```

**问题**：`i` 是循环变量（0,1,2...），但 `connections` 是以 `fd` 为 key 的 map。应该是：
```cpp
recv(connections[events[i].data.fd]);
```

### 2. **Server. Cpp - 遗漏的 unlock ()** ⚠️ 死锁

```cpp
void Server::handleCommand(Socket &sock) {
    std::string message = Handler::handle(std::move(sock.parser().getResult().value()), kvstore);
    queueMutex.lock();
    message_queue.emplace(std::move(message), sock);
    // ❌ 没有 unlock()！死锁！
}
```

**修复**：
```cpp
{
    std::lock_guard<std::mutex> lock(queueMutex);
    message_queue.emplace(std::move(message), sock);
}
```

### 3. **Server. Cpp - 迭代器失效** ⚠️ 多线程 bug

```cpp
threadPool.enqueue([this, it]() {
    handleCommand(it->second);
});
```

**问题**：
- `it` 是 map 的迭代器，被 lambda 捕获
- Worker 线程执行时，主线程可能已经修改了 `connections`，导致 `it` 失效
- 可能访问已删除的元素

**修复**：捕获 fd 而不是迭代器
```cpp
int client_fd = events[i].data.fd;
threadPool.enqueue([this, client_fd]() {
    Socket& sock = connections[client_fd];  // 在Worker线程中重新查询
    handleCommand(sock);
});
```

### 4. **Server. Cpp - 缺少消息队列 flush**

```cpp
void Server::epoll_step() {
    // ... 处理events ...
    // ❌ 没有处理 message_queue 中的消息！
    // 应该在最后调用 flushMessageQueue()
}
```

消息被放入队列但从未发送出去。

### 5. **Server. Cpp - socketparser () 直接访问不安全**

```cpp
it->second.parser().getResult().value()
```

**问题**：如果 parser 没有 result，`.value()` 会抛异常。应该检查：
```cpp
auto opt = it->second.parser().getResult();
if (!opt.has_value()) {
    // 消息不完整，等下一次epoll_step
    return;
}
auto request = std::move(opt.value());
```
